# Root Agent — pre-sharing checklist

The user applies this list inside Grok Bot. Local validation does not count as installation, template preview or a live behavior test. The steps below were **not performed** in this work.

- [ ] The full description and the current eighteen skills were saved to the existing Bot; each one's full text and availability were compared by reopening it. User overlay texts and explicit exception rules were preserved together.
- [ ] It was taken into account that the `/` menu was intentionally removed in desktop Grok Bot v0.68.1 and later. Saving, availability and selection of a same-named definition were assessed separately with supported library/catalog evidence; the absence of the menu was not treated as an installation error. Visibility on mobile or the plugin being installed was not taken to mean all skills were verified. [Compatibility note](INSTALL.md#2-save-and-enable-the-skills).
- [ ] The expected description, the full content of every skill and the two canonical descriptions in roster-management were checked in the template details. Creating the template alone was not counted as proof of complete transfer.
- [ ] Memories, plugins, routines and identity content were reviewed manually; personal information, private task/roster records, secrets, internal URLs and content without sharing rights were removed. It was verified that the only Root Agent routine is the generic end-of-day self-improvement routine (no times, language or records from the publisher) and that no private user profile folder content is included.
- [ ] Required connections and supported Bot messaging were verified in the recipient's environment. It was checked that there is no runtime dependency on the publisher's repository, scripts, custom MCP, files or sessions. It was confirmed that the mandatory behavior is in the description without the optional Lead skills.
- [ ] Public link / Team-only was chosen deliberately; a Team-only template was kept distinct from Publish to Team. The license notice and live test status were kept explicit in the announcement.
- [ ] A separate recipient copy created its own instance/workspace; it did not inherit the publisher's personal records or past approvals. Required access was verified by its own Bot with a safe probe.
- [ ] The app's actual field limits were recorded separately for the description, skills and announcement text; any truncation counted as a failed installation. 6000 characters was not verified as an official limit; a local numeric measurement was not counted as save/preview success.
- [ ] After real evidence was collected for safe live scenarios, the relevant NOT RUN states of the [acceptance scenarios](validation/acceptance.md) were updated separately. A source update was not taken to have updated the existing share link automatically.

Sources: [sharing](https://docs.x.ai/grok-bot/bots#share-a-bot), [template contents and setup](https://x.ai/bot/guides/templates-for-grok-bot), [sharing terms](https://x.ai/legal/bot-sharing-terms). Checked on: 18 October 2026. Automatic privacy filtering is not relied on.
