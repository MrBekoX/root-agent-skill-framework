# Configure and share Root Agent in the desktop app

The user shares the configured Bot through the desktop app's **Share template** action. The official documentation describes this as sharing a Bot's public link. This workspace supplies the English description and skill text; no separate template file or import package is needed.

For remote-control convenience, [SETUP-INSTRUCTIONS.md](SETUP-INSTRUCTIONS.md) contains the current description and all nineteen skill bodies in one attachment. Give it to the intended Bot and ask it to configure that Bot, save/enable the nineteen skills and verify the results. This is a written setup request, not a native import format. A Windows `D:` path refers to the user's local computer, so the Bot needs permitted local-computer access to read that path; otherwise attach the file through the composer. [Local computer access](https://docs.x.ai/grok-bot/computer-and-apps), [file attachments](https://docs.x.ai/grok-bot/files-and-results).

## 1. Set the description

Open the intended Bot's profile, set its name to **Root Agent**, and paste the full contents of [description.md](description.md) into Description. Save and reopen it to verify that all text is present. A truncated host save is a failed setup. Do not shorten a skill body to fit a host limit, and do not keep a shortened variant beside the full text. If the Bot already exists, use it rather than creating a duplicate. [Create and manage Bots](https://docs.x.ai/grok-bot/bots).

## 2. Save and enable the skills

Use all nineteen instruction bodies linked in the [README](README.md) to update any older setup: enumerate the current names, update each matching definition and add every missing one, then save the matching current description. Preserve unrelated skills. Keep all existing User overlay text in descriptions and skills verbatim, together with this version's explicit precedence/exception rules; surface a conflicting additional local overlay before dependent execution rather than silently deleting either rule. Preserve the embedded descriptions, prompt/package forms and identical recipient-resolution block. Reopen each complete saved body and verify availability for Root Agent through supported controls. For private-library inspection, open Connect apps → Your plugins → Manage plugins and skills → Private skills where available; exact UI labels may vary. [Skills and routines](https://docs.x.ai/grok-bot/skills-routines-and-automations).

**Desktop compatibility, checked on 19 October 2026:** Grok Bot v0.68.1 (7 October 2026) intentionally removed the desktop composer's `/` menu. The menu remains available on mobile. Older documentation still describes the former desktop behavior; use the [release notes](https://x.ai/changelog/bot#v0.68.1) and [platform forum explanation](https://forum.cursor.com/t/grok-bot-macos-unable-to-use-see-slash-commands/174932) for this change. Its absence on Windows or macOS is expected and does not justify reinstalling skills or resetting the Bot's computer.

On desktop, request a saved skill by name in an authorized task, for example: "Use the work-control skill to report this task's status." Such a request executes work and is outside the read-only acceptance check. Verify library registration, current-session availability, full saved contents and same-name resolution separately through supported evidence. Do not require an undocumented per-Bot activation record, use `@`/plugin visibility as proof of skill availability, or infer a wrong runtime solely from a Cursor label. An inaccessible or partial catalog leaves the affected claim NOT VERIFIED; an absent desktop menu alone does not.

For a real team task, Root Agent verifies the Lead before creating members with its actual coordinator reference; the changing roster travels in the handoff, not the permanent Lead profile. Root Agent retains every independent-review assignment, including a Reviewer in a domain group. Existing unrelated roles are preserved. The optional [Lead-side skills](../lead-template/README.md) can be installed through supported library/availability controls; no cross-Bot registration capability is assumed, and the canonical Lead description contains the required behavior without them. Standing creation and internal handoff authority comes from the installed description and current owner's instructions, never the publisher's private approvals. Do not pre-create a team or activate monitoring during configuration.

Test written methods with safe real tasks and refine them from the results. Before scheduling recurring work, establish a successful task, saved method, second input test and failure/retry behavior. Root Agent delegates recurring execution to its specialist owner. [Use cases](https://docs.x.ai/grok-bot/use-cases).

## 3. Share the configured Bot

The user handles creation and publication through **Share template** (current documentation: Share → Create template). Inspect **View template details** before choosing **Public link** or **Team-only**; do not rely on the account's default audience. The recipient chooses **Add to Grok Bot** and finishes in the app. A Team-only template creates recipient copies; **Publish to Team** is a different shared Team Bot workflow. [Share a Bot](https://docs.x.ai/grok-bot/bots), [Team Bots](https://docs.x.ai/grok-bot/team-bots).

Use the [sharing checklist](SHARING-CHECKLIST.md) to inspect the actual packaged description, all eighteen full skills, embedded role templates, memories, plugins and routines. Automatic filtering is not a substitute for review. Remove private identities, records and unintended routines. The recipient must initialize its own instance/workspace and verify its own connections. Custom scripts/code and nonstandard MCP dependencies are not a complete transferable environment; this framework requires none of them at runtime. Local validators stay in this repository. [Template guide](https://x.ai/bot/guides/templates-for-grok-bot).

Checked on 18 October 2026: an approximately 6000-character limit was **not verified in official sources** for personal profile instructions, skill bodies or a total template. No validator treats 6000 as a platform limit. The template's promotional text and the profile instruction field must be checked separately in the app. Record the actual field, app/version, measurement unit and save/preview result if a limit appears; never truncate canonical behavior to fit an assumed number.

Source updates, local checks, installed save/readback, template details, recipient-copy tests and live behavior are separate verification states. Repository checks establish only the first two. Follow [third-party sharing terms](https://x.ai/legal/bot-sharing-terms): review confidentiality and content-sharing rights, retain required license notices, and make the framework's instruction-only and untested-live status clear. The repository's MIT permission does not authorize redistribution of unrelated imported content.

For a GitHub-based self-install or upgrade, attach [SETUP-INSTRUCTIONS PROMPT.md](<../SETUP-INSTRUCTIONS PROMPT.md>) from the repository root to the existing Root Agent's conversation. It directs that Bot to fetch current `main` at one resolved commit, derive the version and Root skill set, apply the full configuration through supported controls, and verify readback before removing proven obsolete Root-only installation artifacts. It preserves private working records, User overlays and shared consumers; required platform deletion approvals remain in that conversation. This prompt is a one-time user setup request, not an additional installed skill or a replacement for the generated attachment. Its availability does not establish that self-installation has been tested in Grok Bot.
